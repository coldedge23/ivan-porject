# 個人時間軸地圖

> ⚠️ **這個資料夾含有真實的個人足跡資料，不會被 push 到公開 GitHub repo。**
>
> 本機伺服器只開放地圖需要的檔案（`index.html` 與 `data/*.json`）。原本是把整個資料夾開出去，連 `location-history.json` 和 `scripts/` 都能直接抓；寫檔的 API 也會檢查 `Content-Type`、`Origin` 與 `Host`，擋掉其他網頁跨站來改你的資料。
> `location-history.json`（原始資料）與 `data/`（轉換後的 GeoJSON，含反查出來的真實地址）都已加入根目錄 `.gitignore`。

## 專案目標
Google 時間軸限制只能在手機上查看足跡，這個工具把 Google Takeout 匯出的時間軸資料轉成網頁地圖，在電腦上瀏覽自己的歷史足跡。

## 技術棧
- **地圖**：Leaflet.js + Leaflet.markercluster（停留點叢集顯示）+ OpenStreetMap 圖磚（免費、不需要 API Key）
- **資料轉換**：Python 腳本，把原始 JSON 拆成「年」「年-月」兩種粒度的精簡 GeoJSON
- **前端**：純 HTML + JS，無框架、無後端

## 使用方式

### 1. 取得原始資料
手機「設定 > 位置資訊 > 時間軸 > 匯出時間軸資料」，把匯出的 JSON 存成 `location-history.json` 放在這個資料夾。

### 2.（選用）反查地點名稱
原始資料的停留點只有座標和 `semanticType`（住家/公司/未知），沒有實際地址或店家名稱。想在地圖上看到「正濱國中」而不是只有「Work」的話：

- **雙擊 [`反查地點名稱.bat`](反查地點名稱.bat)**（或 `cd scripts && python geocode_places.py`）

用 OpenStreetMap Nominatim 免費反查服務，依規範限速每秒查 1 筆，查過的地點會存進 `data/place_names.json` 快取，之後只補查新地點，不會重查。**第一次執行如果地點很多（例如 1,800+ 個不重複地點），會需要 30 分鐘左右**，之後就很快了。這步驟可以跳過，跳過就只會顯示 semanticType。

### 3. 轉換資料
```bash
cd scripts
python convert.py
```
會在 `data/` 產生：
- `YYYY-MM.geojson` — 每月一份，月/日視圖用
- `YYYY.geojson` — 每年一份，年視圖叢集用
- `index.json` — 年份/月份清單
- `search_index.json` — 地點搜尋用的全域索引（每個地點的名稱、座標、出現過的月份）
- `daily_stats.json` — 月曆熱力圖用的每日統計（移動距離、停留點筆數）
- `commutes.json` — 通勤分析用（住家↔公司之間每一趟的耗時、距離、交通方式）
- `coverage.json` — 足跡覆蓋用（去過哪些縣市/國家、各自的地點數與造訪次數）

如果 `data/place_names.json` 存在，地點名稱會自動套用進去。

### 4. 開啟地圖（推薦：雙擊批次檔）
`index.html` 用 `fetch()` 載入 `data/` 底下的檔案，直接用瀏覽器開檔案（`file://`）會被 CORS 擋掉，要跑一個本機伺服器才能看。

- **雙擊 [`啟動地圖.bat`](啟動地圖.bat)** — 啟動 `scripts/server.py`（見下方說明）+ 開瀏覽器到 `http://localhost:8000`
- **手機重新匯出資料後，雙擊 [`更新資料.bat`](更新資料.bat)** — 自動重跑轉換

### 5. 地圖上直接修正名稱 / 隱藏記錄 / 釘選常用地點
地圖上點停留點，彈出視窗裡有這幾個按鈕：
- **修正名稱**：輸入正確名稱後直接存檔（存進 `data/place_name_overrides.json`，用 placeId 對應），優先權比自動反查的結果高，之後重新反查、重新匯出資料都不會蓋掉手動修正
- **隱藏這筆**：把這筆記錄從地圖上隱藏（存進 `data/excluded_visits.json`），**不會刪除原始資料**，只是不顯示；想復原就編輯這個檔案刪掉對應項目
- **釘選為常用地點**：把這個地點改用綠色菱形標記（存進 `data/pinned_places.json`），再點一次可取消。住家/公司類的地點是 Google 已經判定好的，會自動標示，不需要也不能手動釘選（彈窗會顯示「★ 常用地點」）

**修正名稱與釘選是即時的**，不會重跑轉換——那兩項只是呈現層的標籤與樣式，`data/*.geojson` 裡一個數字都不會變。轉換產生的檔案永遠只放反查回來的原始名稱與 Google 判定的 `auto` 釘選；人工修正存在 `place_name_overrides.json`、手動釘選存在 `pinned_places.json`，由 `index.html` 在畫面上套用。所以覆寫只有一份真相，不會出現「檔案裡是舊名字、畫面上是新名字」。

> 為什麼要這樣分：名稱被寫進該地點的每一筆造訪記錄，所以改一個常去地點的名字會讓它出現過的每個月檔都要重寫。實測改一個出現在 71 個月份的地點要重寫 **80 個檔案、耗時十幾秒**，但改變的只有一個字串欄位，沒有任何數字不同。交給前端套用之後降到 **0.5 秒**。
>
> 「隱藏這筆」不一樣，它會把記錄從所有計算裡拿掉——通勤配對、每日統計、足跡覆蓋的數字都會變（實測 5 個檔案）——所以那一項仍然會重跑 `convert.py`（約 10 秒），期間按鈕顯示「處理中...」，跑完所有快取一律作廢並重新載入。

同一時間只會有一個修改在跑，開兩個分頁同時改也不會有人的修改被蓋掉。

> ⚠️ 這個鎖只在單一伺服器行程內有效。如果一邊開著地圖、一邊手動執行 `更新資料.bat`，兩邊會同時寫 `data/`，不受保護。要重新轉換時先把地圖的伺服器視窗關掉。

這兩個按鈕會呼叫本機伺服器（`scripts/server.py`）的 API 直接寫檔 + 自動重跑 `convert.py`，存完立即在畫面上看到結果。**這個功能需要用 `啟動地圖.bat`（或手動執行 `python scripts/server.py`）開啟，如果改用最陽春的 `python -m http.server`，按鈕會顯示「連不到伺服器」的錯誤**（純靜態伺服器沒有這兩支 API）。

⚠️ **如果雙擊沒反應、或跳出「已封鎖」（Application Control / Dangerous file extension）訊息**：
這是 Google 雲端硬碟同步幫檔案加上「網際網路來源」標記（Zone Identifier）被 Windows 安控機制擋下，不是真的從網路下載的檔案。用 PowerShell 解除標記即可：
```powershell
Unblock-File "G:\我的雲端硬碟\ivan-porject\tools\個人時間軸管理\啟動地圖.bat"
Unblock-File "G:\我的雲端硬碟\ivan-porject\tools\個人時間軸管理\更新資料.bat"
Unblock-File "G:\我的雲端硬碟\ivan-porject\tools\個人時間軸管理\反查地點名稱.bat"
```

也可以手動下指令（效果一樣）：
```bash
python -m http.server 8000
```
瀏覽器開 `http://localhost:8000`。

## 資料格式說明
Google 時間軸的 `location-history.json` 是陣列，每筆記錄依內容分三種類型：
- `visit` — 停留地點（座標 + 語意類型，如住家/公司）→ 轉成地圖上的紅點
- `timelinePath` — 移動軌跡的座標序列 → 轉成藍色軌跡線
- `activity` — 兩點間的移動段落（含距離）→ 轉成橘色虛線
- `timelineMemory` — 用途不明，目前略過不處理

- [x] 地點搜尋 — 輸入店名/地址搜尋（`data/search_index.json` 全域索引），選中後自動跳到該地點最近一次出現的月份並定位
- [x] 月曆熱力圖 — 工具列「月曆檢視」，一年 12×31 格子圖，顏色深淺代表當天移動距離（單一藍色相由淺到深的 sequential 色階）。格子分三種狀態：**完全沒記錄**用中性灰、**有記錄但沒有移動距離資料**（只有停留或只有軌跡）用米色、有距離才進藍色色階——沒有距離資料不等於當天沒移動，不能混進色階當成 0 公里。滑鼠移過去看當天數字，點格子跳到那天的地圖
- [x] 常用地點標示 — 住家/公司（Google 的 `semanticType` 判定）自動用綠色菱形標記，加上手動釘選（`data/pinned_places.json`）；獨立圖層不參與叢集，所以任何縮放層級都看得到，不會被合併進數字圓圈
- [x] 年度回顧 — 工具列「年度回顧」，一頁看完該年度的總移動距離、有記錄天數、去過幾個地點（含幾個是第一次去）、移動最遠的一天、各交通方式的距離長條圖、最常去的前 5 名地點（不含住家/公司）；最遠的一天和地點排行都可以點擊直接跳到地圖
- [x] 通勤分析 — 工具列「通勤分析」，自動配對住家↔公司之間的移動（中途順路停留不算中斷，超過 5 小時不算通勤），統計上下班趟數與耗時中位數、最快紀錄、出發時間分布長條圖、各交通方式的耗時與距離。耗時分「門到門」（含中途停留，實際體感）與「純移動時間」（只算移動段落）兩種
- [x] 時間分布分析 — 工具列「時間分布」，星期 × 時段的移動熱力圖（看得出通勤尖峰與週末作息差異）、各星期的平均移動距離、平日 vs 週末對比。每個星期出現的天數不同，所以用「平均每天」而不是總和，避免月份長短造成誤導
- [x] 常去地點排行 — 工具列「常去地點」，依地點彙總造訪次數、總停留時數、平均每次停留，可切換排序方式（次數／時數）與排除住家/公司，點任一列跳到該地點的地圖
- [x] 足跡覆蓋 — 工具列「足跡覆蓋」，從反查回來的地址解析縣市/國家，呈現台灣 22 縣市去過幾個（沒去過的用灰底虛線標示）+ 造訪過的國家；可切換全部年份或單一年份；點縣市展開該地的常去地點，再點可跳到地圖
- [ ] 多年同月比較

- [x] 跨日/跨月記錄的歸屬 — 停留與軌跡以「涵蓋到的每一天」為準，不再只算在開始那天。跨夜的停留（全部 9,997 筆 visit 裡有 2,798 筆跨日、131 筆跨月）在每一天都看得到，選 1 月 1 日不會再漏掉跨年夜還在進行中的那筆。跨月的記錄會同時放進每個月的檔案，並用 `homeMonth` 標記原屬月份，讓做加總的面板不會重複計算

- [x] 距離異常剔除 — Google 原始資料裡有一批壞掉的 `distanceMeters`（宣稱移動 13,175 km，但頭尾座標幾乎同一點、時長只有兩分鐘）。轉換時比對「宣稱距離」與「頭尾直線距離」，**兩個條件同時成立**才判定為異常：宣稱距離 > 直線距離 × 3 + 50 km，且推算時速 > 1,000 km/h。實測剔除 27 筆、合計 355,106 km；2013 年的總移動距離原本被虛增 52.8 倍。這些段落仍會畫在地圖上（起訖點是真的），只是不計入距離統計，彈窗顯示「原始資料異常，未採計」

  > 兩個條件缺一不可。只看時速會誤刪 2015-09-13 那趟 2,144 km、時速 1,067 km/h 的真實航班（被 Google 標成 `in subway`，但它的直線距離就是 2,135 km，距離本身是對的）；只看比值會誤刪繞圈折返的路線（走一圈回到原點，直線距離接近 0 是正常的）。也刻意不用直線距離頂替，那是估算值，會讓統計看起來精確但其實是掰的。

- [x] 寫檔完整性 — 三個 API 的「讀檔 → 改 → 寫回 → 重跑轉換」整段由一個鎖序列化（`ThreadingHTTPServer` 下，開兩個分頁同時改會讓兩邊都讀到同一份原始內容，其中一筆修改消失而且兩邊都收到成功）；所有寫入改成「暫存檔 + 原子換名」（`scripts/jsonio.py`），不會留下寫到一半的半截 JSON；API 先驗證欄位型別與長度才落地，之前送 `{"placeId": []}` 會把 `[[]]` 寫進 `pinned_places.json`，導致之後每次轉換都掛掉；`convert.py` 讀狀態檔時也改成跳過格式不對的項目並提示，不會被一個壞值癱瘓整條管線
- [x] 釘選改成指定目標狀態 — API 從「切換」改成收 `pinned: true/false`。原本是先存檔再重跑轉換，重跑失敗回 500，使用者以為沒成功再按一次就把狀態改回去了。現在同一個請求重送幾次結果都一樣，錯誤訊息也會分清楚是「完全沒存到」還是「存好了但重建失敗」
- [x] 只寫內容有變的檔案 — 改一個地點名稱通常只影響一兩個月檔，其餘一百多個內容根本沒變。轉換時先比對內容，一樣就跳過。轉換時間從 18 秒降到約 9 秒，在 Google 雲端硬碟上還省掉整批重新上傳同步

- [x] 住家/公司判定與呈現脫鉤 — 新增 `isHomeWork` 欄位（依整份資料的 `semanticType` 彙總，同一地點結果一致），排除條件用它；`pinSource` 只負責地圖上要不要畫綠色菱形。以前兩個面板各用各的條件，而且都取「該年遇到的第一筆」，但原始檔裡 visit 並非時序排列，手動釘選一家咖啡廳會被「排除住家/公司」當成公司濾掉
- [x] 通勤時間裁切 — 移動段落改成取「與通勤區間實際重疊的部分」。原本用起始時刻判斷，會漏掉在出發前起步、一路開進通勤時段的段落，也會把延續到抵達之後的段落整段算進來（可以做出「門到門 30 分鐘、純移動 60 分鐘」這種不可能的結果）。部分重疊的距離按時間比例分攤，**這是估算值**，完整落在區間內的才是精確值
- [x] 足跡覆蓋的年份範圍一致 — 選了年份之後，展開縣市看到的地點排行、地點數、起訖日期都跟著那一年；未選年份才顯示全期間，標題會標明目前是哪一種
- [x] 輸出跳脫 — 地點名稱可能來自手動修正或 OSM 上別人填的資料，一律當成不可信文字。彈窗標題以前沒跳脫（隔壁的 placeId 反而有），名稱裡放 HTML 標籤會被當成標籤執行

## 已知限制
- 轉換時略過 3,448 筆記錄：其中 3,415 筆是只有單一座標點的 `timelinePath`（資料本身正常，只是連不成線），33 筆是目前不處理的 `timelineMemory`
- 距離異常的判準偏保守，只抓「宣稱距離離譜且時速不可能」的組合。還有 3 筆比值可疑但時速在門檻內（例如宣稱 346 km 但直線只有 6.5 km、時速 187 km/h）未被剔除，合計約 900 km，佔已剔除量的 0.25%，暫不調鬆門檻以免誤刪真實記錄
- 已載入的年/月份會存在瀏覽器記憶體快取，不重複下載，但重新整理頁面後快取會清空
- 移動軌跡（藍線）、移動段落（橘線）在年視圖沒有叢集，資料多的年份可能會看起來很密，可以先用圖層開關關掉
- 地點反查用免費的 Nominatim + Overpass 服務，依規範限速，不能拿來做大量商業查詢；`data/place_names.json` 是本機快取，重新匯出資料後只會補查新地點
- Overpass（地標搜尋那段）是公用免費伺服器，尖峰時段常常很塞，實測過整批 1,827 個地點要跑 30 小時以上；**建議找離峰時段（例如睡前）雙擊 `反查地點名稱.bat` 讓它整晚跑**，不要在白天等
- 曾嘗試換成 HERE API（速度快、資料完整度更好），但帳號申請卡在 HERE 消費者帳號/開發者帳號兩套系統搞混，先擱置，之後有空再處理
