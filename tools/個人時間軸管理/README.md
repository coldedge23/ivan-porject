# 個人時間軸地圖

> ⚠️ **這個資料夾含有真實的個人足跡資料，不會被 push 到公開 GitHub repo。**
> `location-history.json`（原始資料）與 `data/`（轉換後的 GeoJSON，含反查出來的真實地址）都已加入根目錄 `.gitignore`。

## 專案目標
Google 時間軸限制只能在手機上查看足跡，這個工具把 Google Takeout 匯出的時間軸資料轉成網頁地圖，在電腦上瀏覽自己的歷史足跡。

## 技術棧
- **地圖**：Leaflet.js + Leaflet.markercluster（停留點叢集顯示）+ OpenStreetMap 圖磚（免費、不需要 API Key）
- **資料轉換**：Python 腳本，把原始 JSON 拆成「年」「年-月」兩種粒度的精簡 GeoJSON
- **前端**：純 HTML + JS，無框架、無後端

## 使用方式

### 1. 取得原始資料
手機「設定 > 位置資訊 > 時間軸 > 匯出時間軸資料」，把匯出的 JSON 存成 `location-history.json` 放在這個資料夾。

### 2.（選用）反查地點名稱
原始資料的停留點只有座標和 `semanticType`（住家/公司/未知），沒有實際地址或店家名稱。想在地圖上看到「正濱國中」而不是只有「Work」的話：

- **雙擊 [`反查地點名稱.bat`](反查地點名稱.bat)**（或 `cd scripts && python geocode_places.py`）

用 OpenStreetMap Nominatim 免費反查服務，依規範限速每秒查 1 筆，查過的地點會存進 `data/place_names.json` 快取，之後只補查新地點，不會重查。**第一次執行如果地點很多（例如 1,800+ 個不重複地點），會需要 30 分鐘左右**，之後就很快了。這步驟可以跳過，跳過就只會顯示 semanticType。

### 3. 轉換資料
```bash
cd scripts
python convert.py
```
會在 `data/` 產生：
- `YYYY-MM.geojson` — 每月一份，月/日視圖用
- `YYYY.geojson` — 每年一份，年視圖叢集用
- `index.json` — 年份/月份清單
- `search_index.json` — 地點搜尋用的全域索引（每個地點的名稱、座標、出現過的月份）
- `daily_stats.json` — 月曆熱力圖用的每日統計（移動距離、停留點筆數）
- `commutes.json` — 通勤分析用（住家↔公司之間每一趟的耗時、距離、交通方式）
- `coverage.json` — 足跡覆蓋用（去過哪些縣市/國家、各自的地點數與造訪次數）

如果 `data/place_names.json` 存在，地點名稱會自動套用進去。

### 4. 開啟地圖（推薦：雙擊批次檔）
`index.html` 用 `fetch()` 載入 `data/` 底下的檔案，直接用瀏覽器開檔案（`file://`）會被 CORS 擋掉，要跑一個本機伺服器才能看。

- **雙擊 [`啟動地圖.bat`](啟動地圖.bat)** — 啟動 `scripts/server.py`（見下方說明）+ 開瀏覽器到 `http://localhost:8000`
- **手機重新匯出資料後，雙擊 [`更新資料.bat`](更新資料.bat)** — 自動重跑轉換

### 5. 地圖上直接修正名稱 / 隱藏記錄 / 釘選常用地點
地圖上點停留點，彈出視窗裡有這幾個按鈕：
- **修正名稱**：輸入正確名稱後直接存檔（存進 `data/place_name_overrides.json`，用 placeId 對應），優先權比自動反查的結果高，之後重新反查、重新匯出資料都不會蓋掉手動修正
- **隱藏這筆**：把這筆記錄從地圖上隱藏（存進 `data/excluded_visits.json`），**不會刪除原始資料**，只是不顯示；想復原就編輯這個檔案刪掉對應項目
- **釘選為常用地點**：把這個地點改用綠色菱形標記（存進 `data/pinned_places.json`），再點一次可取消。住家/公司類的地點是 Google 已經判定好的，會自動標示，不需要也不能手動釘選（彈窗會顯示「★ 常用地點」）

按下按鈕後伺服器會重跑 `convert.py`（約 11 秒），期間按鈕會顯示「處理中...」，跑完畫面自動更新。

這兩個按鈕會呼叫本機伺服器（`scripts/server.py`）的 API 直接寫檔 + 自動重跑 `convert.py`，存完立即在畫面上看到結果。**這個功能需要用 `啟動地圖.bat`（或手動執行 `python scripts/server.py`）開啟，如果改用最陽春的 `python -m http.server`，按鈕會顯示「連不到伺服器」的錯誤**（純靜態伺服器沒有這兩支 API）。

⚠️ **如果雙擊沒反應、或跳出「已封鎖」（Application Control / Dangerous file extension）訊息**：
這是 Google 雲端硬碟同步幫檔案加上「網際網路來源」標記（Zone Identifier）被 Windows 安控機制擋下，不是真的從網路下載的檔案。用 PowerShell 解除標記即可：
```powershell
Unblock-File "G:\我的雲端硬碟\ivan-porject\tools\個人時間軸管理\啟動地圖.bat"
Unblock-File "G:\我的雲端硬碟\ivan-porject\tools\個人時間軸管理\更新資料.bat"
Unblock-File "G:\我的雲端硬碟\ivan-porject\tools\個人時間軸管理\反查地點名稱.bat"
```

也可以手動下指令（效果一樣）：
```bash
python -m http.server 8000
```
瀏覽器開 `http://localhost:8000`。

## 資料格式說明
Google 時間軸的 `location-history.json` 是陣列，每筆記錄依內容分三種類型：
- `visit` — 停留地點（座標 + 語意類型，如住家/公司）→ 轉成地圖上的紅點
- `timelinePath` — 移動軌跡的座標序列 → 轉成藍色軌跡線
- `activity` — 兩點間的移動段落（含距離）→ 轉成橘色虛線
- `timelineMemory` — 用途不明，目前略過不處理

- [x] 年度回顧 — 工具列「年度回顧」，一頁看完該年度的總移動距離、有記錄天數、去過幾個地點（含幾個是第一次去）、移動最遠的一天、各交通方式的距離長條圖、最常去的前 5 名地點（不含住家/公司）；最遠的一天和地點排行都可以點擊直接跳到地圖

- [x] 時間分布分析 — 工具列「時間分布」，星期 × 時段的移動熱力圖（看得出通勤尖峰與週末作息差異）、各星期的平均移動距離、平日 vs 週末對比。每個星期出現的天數不同，所以用「平均每天」而不是總和，避免月份長短造成誤導

## 已知限制
- 轉換時略過約 3,448 筆（約 9%）格式無法解析的記錄，多為異常資料
- 已載入的年/月份會存在瀏覽器記憶體快取，不重複下載，但重新整理頁面後快取會清空
- 移動軌跡（藍線）、移動段落（橘線）在年視圖沒有叢集，資料多的年份可能會看起來很密，可以先用圖層開關關掉
- 地點反查用免費的 Nominatim + Overpass 服務，依規範限速，不能拿來做大量商業查詢；`data/place_names.json` 是本機快取，重新匯出資料後只會補查新地點
- Overpass（地標搜尋那段）是公用免費伺服器，尖峰時段常常很塞，實測過整批 1,827 個地點要跑 30 小時以上；**建議找離峰時段（例如睡前）雙擊 `反查地點名稱.bat` 讓它整晚跑**，不要在白天等
- 曾嘗試換成 HERE API（速度快、資料完整度更好），但帳號申請卡在 HERE 消費者帳號/開發者帳號兩套系統搞混，先擱置，之後有空再處理
